# Passive Grid Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first trustworthy research milestone for Grid-trade: deterministic passive-order contracts, S0 fixed long grid generation, cancel-before-replace reconciliation, hard risk vetoes, immutable evidence, hftbacktest-backed microstructure replay, and a NautilusTrader post-only execution mapping.

**Architecture:** Strategy intent remains runtime-neutral. `grid_trade.strategy` produces desired passive ladders from causal market state, `grid_trade.execution` reconciles those ladders against working orders, `grid_trade.risk` can veto or de-risk independently, and integrations translate the resulting intents into hftbacktest/NautilusTrader without leaking exchange/runtime types into the domain. The first milestone implements only S0 fixed long grid; adaptive center, volatility spacing, inventory target, short overlay, funding bias, OFI/microprice, and RL remain out of scope until later ablation stages.

**Tech Stack:** Python 3.12; uv; pytest 9.1.1; Hypothesis 6.165.2; Ruff 0.15.22; mypy 2.3.0; NautilusTrader 1.230.0; hftbacktest 2.4.4.

## Global Constraints

- Repository license remains LGPL-3.0.
- Initial research target is a single crypto perpetual instrument; BTC is the default research candidate.
- Production status remains NO-GO throughout this milestone.
- No live-capital path, private keys, or automatic production authorization.
- OHLC-only results cannot authorize promotion; Tier-2 microstructure replay is required for strategy evaluation.
- Long-to-short and short-to-long transitions must pass through an observed flat state; this milestone does not open short exposure.
- Hard risk controls are deterministic and may veto strategy intent.
- No future leakage; all state objects are timestamped and causal.
- Third-party code is not copied unless attribution/license requirements are explicitly recorded. Prefer dependency use or independent implementation from published algorithms.
- Development is TDD: failing test, minimal implementation, passing focused test, then commit.
- Keep files focused and interfaces runtime-neutral.

### Task 4: Passive working-order reconciliation state machine

**Files:**
- Create: `src/grid_trade/execution/reconcile.py`
- Create: `tests/execution/test_reconcile.py`

**Interfaces:**
- Consumes: desired `PassiveOrderIntent` sequence and actual `WorkingOrder` sequence.
- Produces: `reconcile_passive_orders(...) -> ReconciliationPlan`.

- [ ] **Step 1: Write failing tests for the four core states**

Test:

1. no working orders -> submit entire desired ladder;
2. exact working ladder -> no actions;
3. stale generation or mismatched price/quantity -> cancel stale IDs only and submit nothing in the same cycle;
4. after terminal cancellation is observed -> submit the desired replacement generation.

- [ ] **Step 2: Write partial-fill tests**

A partially filled working order with matching generation/price remains working for its remaining quantity. A desired quantity below already-filled quantity is invalid and raises `ValueError`; reconciliation must never manufacture negative remainder.

- [ ] **Step 3: Verify RED**

Run: `uv run pytest tests/execution/test_reconcile.py -v`.

- [ ] **Step 4: Implement cancel-before-replace**

Algorithm:

```python
if any_conflicting_working_order:
    return ReconciliationPlan(cancel=conflicting_ids, submit=())
if any_unknown_or_duplicate_client_id:
    raise ValueError(...)
return ReconciliationPlan(cancel=(), submit=missing_desired_orders)
```

Sort cancellation IDs and submissions deterministically by `(side.value, level, client_order_id)` before constructing the frozen plan.

- [ ] **Step 5: Add idempotence property test**

Applying reconciliation against a working set already equal to desired must always produce the empty plan, independent of input tuple ordering.

## Milestone Review Gate

Milestone 1 is complete only when all of the following are true:

- S0 fixed-long grid geometry is deterministic and fully tested.
- Passive working-order reconciliation is idempotent and cancel-before-replace.
- Partial fills cannot create negative remainder or duplicate replacement risk.
- Risk breaches fail closed and can force passive cancellation/flat intent.
- Evidence is canonical and repeatable across fresh processes.
- hftbacktest 2.4.4 replay is behind a narrow adapter and reproduces the synthetic fixture exactly.
- NautilusTrader 1.230.0 post-only order construction is covered without venue submission.
- Full pytest, Ruff, formatter, and strict mypy gates pass.
- No S1-S7 adaptive logic, live secrets, or production authorization has leaked into this milestone.
